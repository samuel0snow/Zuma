# Zuma · CLI 与本地 GUI

基于 `Zuma 实现方式.md` 和 `Zuma/Zuma.md` 的 C++17 祖玛游戏。原始两个关卡保留在 `Zuma/`。CLI 与本地网页 GUI 共享同一个规则核心；中期包含 A–E 的核心适配、服务、交互、动画及交付验证。CLI 不需要第三方库，GUI 的 HTTP/JSON 依赖已附源码和许可，无需联网安装。

## 启动 GUI

完成下方 CMake 构建后，在项目根目录运行：

```powershell
.\build\zuma_gui.exe
```

打开浏览器访问 **http://127.0.0.1:8080**。选择经典或特殊模式、选择关卡，点击轨道上方的编号发射，或丢弃当前球。重启返回玩法选择，全部状态重新开始。终端按 Ctrl+C 停止服务。网页需要通过这个服务打开，不能双击 HTML 代替启动服务。

端口占用时用 `.\build\zuma_gui.exe --port 8082` 并访问相应端口。可用 `--levels 目录` 与 `--web 目录` 指定关卡和页面位置。`--test-mode` 仅供测试允许指定种子，普通启动不接受前端设置种子。

页面支持刷新恢复服务内的当前游戏；服务关闭后游戏不保存。每个回合按核心事件依次播放发射、消除、连锁、属性与入轨动画，最后校正到服务快照；期间禁用游戏操作，可以点击“跳过动画”。系统减少动态效果设置下直接显示最终状态，动画异常也不会改变规则或丢失服务结果。请求或同步失败会暂停操作，可点击“重新连接”，不会自动重发发射。多个页面共享单个活跃游戏，旧版本操作会被拒绝并同步。

GUI 只监听本机地址。运行不需要 Node、npm 或 Python。美术资源建议见 [Zuma 美术资源需求.md](Zuma%20美术资源需求.md)，免费素材来源见 [美术资源候选清单](docs/美术资源候选清单.md)。页面已接入筛选后的球、图标、纹理、特效与自制背景/底座，来源和改动记录见 `web/assets/CREDITS.md`；实际截图及验证见 [中期验证记录](docs/中期验证记录.md)。

运行包与源码包可通过 `python tools/package-release.py` 生成到 `build/releases/`。详细解压启动、许可与打包说明见 [运行与交付说明](docs/运行与交付说明.md)。

## 编译与运行

需要支持 C++17 的编译器（MinGW GCC、Clang 或 MSVC）和 CMake 3.16+。在项目根目录执行：

```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
.\build\zuma.exe
ctest --test-dir build --output-on-failure
```

Visual Studio 开发者终端可以使用：

```powershell
cmake -S . -B build
cmake --build build --config Release
.\build\Release\zuma.exe
.\build\Release\zuma_gui.exe
ctest --test-dir build -C Release --output-on-failure
```

不使用 CMake 时，也可以在根目录直接编译：

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic -static -I include src/main.cpp src/game.cpp src/level.cpp -o zuma.exe
.\zuma.exe
```

Linux/macOS 使用相同源码：`cmake -S . -B build`、`cmake --build build`、`./build/zuma`。CMake 构建后将关卡复制到可执行文件旁的 `levels/`，多配置构建也适用。程序优先查找可执行文件旁的 `levels/`，再查找工作目录下的 `Zuma/` 和 `levels/`；可用 `--levels 路径` 指定关卡目录。打包时将可执行文件与包含两个关卡的 `levels/` 文件夹一起分发。

GUI 在 Linux/macOS 使用 `./build/zuma_gui`。GUI 打包需同时包含 `zuma_gui`、`levels/`、`web/`、`third_party/` 中的许可说明；CMake 默认构建会复制这些资源。修改网页后再次运行 `cmake --build build` 即可同步资源，无须 npm 构建。

本机混装 MinGW 可能存在头文件默认 CRT 与标准库 ABI 不匹配。CMake 会用 streambuf 链接检查检测，只有默认失败且 MSVCRT 兼容检查通过时才启用项目级兼容定义，不修改编译器安装。若两种检查都失败，应使用完整配套的工具链。

## 操作与规则

- 启动先输入 `1` 添加特殊属性或 `2` 使用普通模式，再输入 `1` 或 `2` 选择关卡。
- 输入 `1…n+1` 发射，位置表示原第 i 个球之前，`n+1` 表示末尾；空轨道只有位置 `1`。
- `q` 丢弃当前球；`exit` 主动退出，不计回合、不算失败。输入结束也会退出。
- `restart` 重启整个游戏，返回“是否添加特殊属性”的起始界面；旧局全部状态丢弃，重新选择模式与关卡后从零开始，不计回合、不算失败。游戏结束后也可使用此命令。
- 空输入、非整数、数字后附带字符和越界位置均报错，全部状态保持不变。
- 有效回合依次执行：插入或丢弃 → 普通及全部连锁消除 → 一个等待球从轨道最前端进入 → 循环弹药前移并增加回合数 → 判断胜负。
- 连续至少三个同色球整段消除，每球 10 分。仅检查插入球及消除断口；丢弃和等待球进入不触发消除。
- 轨道与等待区同时为空则胜利；轨道长度超过上限则失败。等于上限仍可发射，完成整个回合才判断。
- 结束后输入 `r` 返回选择关卡，创建全新状态，或输入 `exit` 退出。

实现文档最后的鲁棒性条目与前面的严格位置校验冲突：初期采用前文规定，超出 `n+1` 一律报错，不自动转换为末尾位置。

支持 ANSI 的终端中，轨道、弹药和等待区使用红、绿、蓝、黄、紫文字，并保留 R/G/B/Y/P 字母。Windows 自动尝试启用虚拟终端颜色；不支持颜色、输出重定向或设置 `NO_COLOR` 环境变量时使用纯文本。胜利和失败以独立结果框展示，支持颜色时分别使用醒目的绿色和红色。

每个有效回合结束后，终端清屏并显示最新状态及本回合效果提示；非法输入不会清屏。重定向到文件时保留完整日志。

## 特殊属性

CLI 在关卡选择前询问是否添加特殊属性：`1` 启用并显示属性说明，`2` 使用普通模式。重新选择关卡时也可重新选择模式。是否启用由 CLI 传入核心，核心默认不添加属性。启用时，初始轨道球和首次进入轨道的等待球有 10% 概率携带属性，Back、Stop、Boom 等概率选择；每局使用当前时间作为随机种子。发射球不携带属性。属性显示在所属球正下方，颜色匹配仍只依据字母。效果提示与停滞剩余回合在支持 ANSI 的终端中显示为红色，Boom 提示的格号依据本次消除前（已插入发射球）的轨道位置。

属性球被普通消除、连锁消除或炸弹清除时触发一次：

- **Back**：消除阶段结束后，将轨道最前端最多 3 个球按原顺序放到等待队列最前端，保留颜色及属性，不重新抽取。随后仍执行本回合正常增长，因此未停滞时其中一个球会立即重新入轨。多个 Back 依次执行。
- **Stop**：从下一有效回合开始，连续两个回合不加入等待球；触发回合的增长照常，多个 Stop 累加暂停回合。非法输入不减少暂停时间。
- **Boom**：以消除前的炸弹位置为中心，清除左右各最多 3 格（连同自身），越过端点时截断。范围内其他属性也触发，炸弹可以引爆其他炸弹；每颗实际消除的球仍只计 10 分。扩大范围后继续检查断口的同色连锁。

以上明确了实现文档未指定的触发时机及“3 格”的范围解释。丢弃、后退和自动增长本身不触发属性；规则核心默认不随机附加属性，CLI 显式启用，测试可指定随机种子与初始属性以复现结果。

## 模块与数据结构

| 模块/结构 | 用途与原因 |
| --- | --- |
| `src/level.cpp` | 按行解析字段；验证缺失、重复、未知字段、颜色、正整数和初始长度；支持 CRLF、空白行及 UTF-8 BOM。 |
| `src/game.cpp` / `include/zuma.hpp` | 独立规则核心，不依赖 CLI 输入输出，可由后续 GUI 调用。 |
| `src/main.cpp` | 关卡选择、严格命令解析、状态显示、错误提示及重新选择。 |
| `src/server/api.cpp` | 游戏会话、严格 JSON 校验、版本控制、重复请求缓存、状态及结构化事件序列化。 |
| `src/server/main.cpp` | 本机 HTTP、同源检查、资源白名单、请求体限制；依赖版本与许可见 `third_party/README.md`。 |
| `web/` | 无构建依赖的 HTML/CSS/JavaScript，模式/关卡/游戏/结果界面；显示服务结果，不重新计算规则。 |
| `web/animation.js` | 稳定球 ID 的移动、消除、属性图集播放；每阶段展示核心快照，支持跳过和减少动态效果。 |
| `vector<char>` | 循环弹药，用下标和取模访问当前球、下一球。 |
| `list<Ball>` | 轨道，节点保存颜色、属性，支持插入、向左右扩展及区间删除；位置定位需要遍历。删除时只保留仍有效的断口迭代器。 |
| `queue<Ball>` | 等待区，按先进先出顺序每有效回合取一个球。Back 使用临时队列将退回球放在现有等待球之前。 |

## 验证与演示

核心构造时也校验颜色、容量、弹药和初始属性配置；极大容量最多额外展开 20 个空格，其余显示数量。健壮性复查记录见 `Zuma 实现方式.md`，中期设计见 `Zuma 中期建设方案.md`。

`tests/tests.cpp` 覆盖普通消除、多级连锁、断口不足三个、丢弃与自动增长不消除、弹药循环、非法操作不改变状态、空轨道、满轨道发射、胜负及关卡格式错误。

选择普通模式时，原始关卡 1 首回合输入 `4`：消除三个 B 和四个 R，得分 70，随后等待区的 G 入轨，回合数 1，游戏继续。输入 `q` 演示自动增长及弹药更新。连续输入空行、`abc`、`2x`、`0` 和越界数演示无效输入。GUI 中对应点击位置 4。

可将临时演示目录中的 `level1.txt` 写为 `ACTIVE=RR`、`FEED=`、`AMMO=R`、`MAX_LENGTH=2`（每字段一行），用 `--levels` 指向该目录；输入 `2` 即普通消除并胜利。原始附件无需修改。课堂报告与截图 PDF 不属于本次 CLI 搭建产物。
