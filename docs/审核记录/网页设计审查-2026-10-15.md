# Zuma 当前桌面界面审查

日期：2026-10-15。本轮只审查、保存证据，不修改界面代码。保留深绿庭院、暖金和宝石球的既有方向，不引入手机场景。

## 方法与范围

依据 [distinctive-ai-design](https://github.com/houxin0010/distinctive-ai-design/blob/main/SKILL.md) 和[截图评审参考](https://github.com/houxin0010/distinctive-ai-design/blob/main/references/review-and-media.md)，围绕识别颜色、瞄准、发射与理解结果，检查构图、层级、文字、素材整合和操作反馈。本轮为同一上下文自查，没有独立评审者；不以主观评分代替功能验证。

Playwright 启动当前编译程序的独立 8098 端口服务，覆盖 1280×720、1920×1080 的模式、特殊属性说明、地图选择、关卡选择、第三关三张地图、一次螺旋发射、主动结束和复盘，共 20 张实际截图。截图前等待界面空闲并移走鼠标，避免把加载或悬停样式当作静态界面。服务已关闭。沿用本机依赖，没有下载或安装新依赖；本轮文件均在 D 盘项目内。

证据目录：[截图与尺寸数据](screenshots/design-review-2026-10-15/measurements.json)。尺寸指浏览器中的实际显示尺寸，不是 CSS 声明值。

## 其他可用性与审美问题

1. **等待区的视觉权重过大。** [1280 直线](screenshots/design-review-2026-10-15/1280-straight.png)中，24 颗等待球和完整实色卡片比主舞台更醒目。保持等待区功能，但减少容器强调，优先释放空间给当前球和轨道；必要时将详细队列折叠为可展开区域。
2. **背景与舞台重复取景，空间衔接生硬。** [1920 S 形](screenshots/design-review-2026-10-15/1920-s.png)中，页面已经是庭院，舞台内部又出现另一套裁切的同张庭院，顶部枝叶与地砖尺度发生跳变。建议舞台使用较安静的石面底层，页面背景继续承担环境氛围。
3. **瞄准反馈离注意中心较远。** 状态集中在舞台左下角，直线图的插入预览、球心分界线和终点又随地图一起缩小。建议突出目标附近的插入标记，详细说明保留在固定状态区；吐球提示应继续明确说明会消耗回合。
4. **“结束本局”和“重启游戏”区分不够直观。** 顶部两个小字操作相邻；目前重启返回玩法选择，结束则保留复盘入口。建议把前者的真实作用写清楚，例如“返回选择”，并区分外观与说明，减少误触后的困惑。本轮未开展用户误触实验。
5. **地图预览和实景的完成度落差明显。** [地图选择](screenshots/design-review-2026-10-15/1280-maps.png)使用粗线与圆点，进入后却是精细宝石和金属底座；螺旋预览也不完全反映当前实际路径。可以用真实地图几何生成简洁预览，保留少量石轨质感和统一发射台标记，不必新增大图素材。
6. **关卡卡片用高度对齐掩盖了内容差异。** [关卡选择](screenshots/design-review-2026-10-15/1280-levels.png)中，第一关球组到容量说明之间留白较大，第三关则较充实。建议在统一预览区域加入“初始球数”信息，并压缩无意义高度；不恢复与关卡无关的名称，也不凭空添加难度等级。

## 已确认的改善与边界

- 当前球和下一球已位于同一发射位置附近，材质保持统一。上一轮三地图浏览器验证已确认发射中空槽、弹药更新后补球；本轮不把这个已修复问题重复列为缺陷。
- 本轮 18 个非复盘状态均没有页面横向或纵向溢出；两张复盘长图分别为 1461px、1802px 高，符合静态长流程的既定形式，不作为需要强制压成一屏的问题。
- 模式选择的属性说明在本轮两种桌面尺寸下保持一屏，旧审查中的该项不再成立。
- 本轮未覆盖自然胜利、自然失败、多回合长复盘、键盘全流程、色觉差异用户、所有关卡和所有动画帧，因此不宣称完成这些项目的验收。颜色对比度未做逐项定量测量。

建议第一轮仅处理：直线地图空间与显示尺寸、特殊属性标记可读性、终局状态一致性。第二轮再处理侧栏权重、舞台背景与地图预览的一致性，沿用现有主题和素材。

## 修复与验收（2026-10-15）

以上问题已按两轮完成修复，保留本节之前的文字作为审查时的问题快照。

| 审查项 | 实际修改 | 验收证据 |
| --- | --- | --- |
| 直线地图过扁、发射台过小 | 根据轨道长度扩大发射区纵向空间，预留底座与下一球边界；发射台显示尺寸独立于世界坐标缩放 | 三种桌面尺寸、三张地图、三个关卡共 27 组检查：当前球至少 48px、下一球约 34px，完整显示且页面无溢出 |
| 特殊属性难读 | 图标至少 14px，文字在空间足够时保持 12px；紧凑轨道使用图标，保留悬停说明和可聚焦的属性名称，焦点进入时在舞台状态区显示解释 | 固定种子的特殊属性模式，27 组检查验证图标尺寸与边界；点击属性标记不发射 |
| 终局提示矛盾 | 主动结束显示“本局已结束”，隐藏下一球并弱化发射台；自然胜负继续使用对应状态 | 实际主动结束、失败和复盘入口检查通过；减少动态效果下连续丢弃可自然失败 |
| 等待区抢眼 | 容器降低不透明度与阴影，球体缩至 24px，保留完整等待序列 | 最终截图确认侧栏层级减弱，信息仍可见 |
| 背景重复 | 舞台使用安静的深绿石面色调，不再重复裁切庭院图片 | 浏览器检查舞台背景不包含庭院图片，截图复查通过 |
| 瞄准反馈过小 | 插入标记半径至少 7px，线宽约 2px，入口及终点标签按屏幕尺寸保持可读 | 三地图截图保留目标附近的插入标记，固定文字提示仍说明命中或吐球 |
| 返回与结束含义模糊 | “重启游戏”改为“返回选择”，悬停解释当前局及复盘会被清除；结束按钮使用独立的暖色边框 | 截图及实际结束、返回流程通过 |
| 地图预览简陋且不一致 | `/api/maps` 保留原有 id/title，新增实际服务几何；预览使用相同路径、石轨色调及现有宝石与底座素材 | 浏览器逐一比较三张预览的轨道点与接口几何，完全一致；没有新增图片素材 |
| 关卡卡片空白与信息不足 | 压缩球组间距和预览区域，补充初始球数、容量和等待球数 | 三张关卡卡片均显示初始数量，按钮对齐，最终截图复查通过 |

第一轮截图发现放大的底座在直线图下方被裁切，第二轮增加服务几何的底部预留后修复；入口、终点文字也增加安全边距，未以通过页面溢出检查代替部件完整性检查。
