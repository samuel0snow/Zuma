# 网页再建设报告

日期：2026-10-14。依据：《网页设计审查-2026-10-14》。范围为桌面浏览器；保留古庭院、五色宝石和石质铜饰底座，不增加手机场景，不改变核心规则。先形成方案，再修复和验收。

## 建设方向

让轨道成为游戏画面的中心，当前球成为明确的操作起点。统计和解释退到次级层级；用布局、删减与准确反馈完善现有素材，不通过新增装饰掩盖问题。

## 问题与验收清单

| 编号 | 修复方案 | 验收标准 |
| --- | --- | --- |
| R1 游戏页仪表盘感 | 得分、回合缩为次级状态带；轨道与底座合为一块舞台，发射台改为轨道下方的操作区。容量仅在轨道旁展示一次，不再重复空间文字和进度条。 | 游戏主球在常用桌面窗口比旧版 48px 更大；两关满轨道及超限状态所有球和间隙完整可见。轨道视觉面积和层级高于统计栏。 |
| R2 特殊模式超过单屏 | 固定介绍区域顶部基线；只显示三条短属性摘要和总概率，完整教学放在规则弹窗。 | 1280×720、1366×768、1920×1080 的普通/特殊模式、关卡选择和游戏主状态无页面滚动；切换模式时介绍标题不跳动，选择关卡按钮始终可见。 |
| R3 日志与终局矛盾 | 合并同类效果形成一句摘要，逐事件消息放入可展开详情。零回退显示“无彩球可回退”，不重复打印。胜败时隐藏无关回合提示及发射操作，只保留结果与重新开始。 | 核心产生的 Stop/Back/Boom 与连锁结果准确汇总；详情可访问。胜利和失败均无“选择下一步”提示，无可见发射/丢弃或重复重启按钮。 |
| R4 重复关卡编号 | 删除巨大装饰编号，只展示关卡编号、真实初始序列、容量及等待数量，按钮统一为“开始游戏”。 | 两关均无虚构名称和三重编号，实际数据与 API 一致。 |
| R5 重复教学 | 首页保留一句玩法简介；删除重复节奏提示、增长脚注及关卡页教学。规则弹窗保留完整说明。 | 玩家可以发现规则入口，模式选择与关卡入口清楚，单屏不依赖隐藏必要规则。 |
| R6 游戏页常驻次要信息 | 游戏中仅显示模式名；概率留在玩法页和规则中。去掉页脚颜色清单，署名入口保留并降低权重。 | 模式与特殊状态明确，游戏页没有常驻概率说明；素材许可入口始终可访问。 |
| R7 球槽接触不明确 | 调整球与底座相对位置，加入克制接触阴影；不重新生成素材。 | 检查正常尺寸和局部截图：球下沿落在球槽，阴影位于接触处，不压住底座正面的铜饰。 |
| R8 小尺寸纹理噪点 | 增大轨道及当前球，等待队列作为次级区域展示，避免纹理与主球竞争。 | 五色在轨道清楚可分，等待区更克制；图片加载失败时纯色回退仍可辨识，不恢复可见字母。 |

## 实施与验证

第一轮实施主舞台、模式页单屏与文案删减；第二轮校正结果摘要、终局、底座接触及截图发现的细节。审查建议的“两轮”用于视觉精修，缺陷修复和验收不以轮次为由提前停止。

使用实际服务验证选择、发射、丢弃、跳过动画、重启与同步；使用真实 C++ 核心导出的快照验证胜利、失败及特殊属性，测试渲染数据不冒充实际关卡。逐窗口检查页面高度、轨道边界、按钮可点击性和图片回退，并保存修复后截图。验证不向 C 盘下载；沿用本机浏览器，临时文件写入 D 盘。

## 最终验收记录

已完成 R1–R8。桌面端自动检查覆盖 1280×720、1366×768、1920×1080 的普通模式、特殊模式、关卡选择、两关初始/满轨道/失败状态，以及胜利、特殊效果摘要、展开详情、动画帧和素材缺失回退，共 34 项状态检查；所有状态均无横向或纵向页面溢出。实际 GUI 服务上的浏览器回归覆盖 13 种渲染状态和普通发射、连锁、丢弃、跳过、重启、Back/Boom/Stop、第二关等流程，均通过。桌面截图见 `docs/screenshots/网页再建设-2026-10-14/`。球体与球槽接触截图已保存，主球高于等待球，球的贴图加载失败时仍可用纯色识别。\n\n最后一次全量 CTest 中规则、API 规则和动画跟踪 3 项通过；HTTP 合约测试在沙箱启动其临时子进程后未能连接本机回环服务（`server did not become ready`）。单独启动相同 GUI 服务可正常监听，但本轮自动化复跑受浏览器本机网络访问限制（`ERR_NETWORK_ACCESS_DENIED`），因此 HTTP 合约项记为环境限制，未把它计作通过。此前本次实施中的浏览器服务回归已成功完成。
