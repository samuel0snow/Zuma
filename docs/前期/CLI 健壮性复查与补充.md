## CLI 健壮性复查与补充（2026-10-13）



### 已完成的改进



- **缺失文件诊断**：使用 `is_open()` 明确检查关卡及目录探测文件是否打开，缺失文件报告“无法打开关卡文件”，不混淆成缺少字段；已增加回归测试。

- **核心配置校验**：除文件解析外，`Game` 构造函数也验证 ACTIVE、FEED、AMMO 的颜色、非空弹药、正容量、初始长度、属性概率范围 0…100、初始属性数量和属性枚举。后续 GUI 直接调用核心时也不能绕过这些检查。

- **极大容量显示保护**：轨道中的球全部展示，空格最多额外展开 20 格；其余空格显示数量，避免合法但极大的 MAX_LENGTH 导致巨量输出。此措施只限制显示，不改变游戏容量和合法插入位置。

- **关卡选择阶段重启**：输入 restart 可返回属性模式选择；游戏进行中重启清屏、丢弃旧局，重新选择后初始化全部状态。主动重启不是游戏失败，也不是有效回合。

- **构建资源定位**：CMake 在构建完成后将原始关卡复制到可执行文件旁的 levels/，兼容普通及多配置输出目录。支持 --levels 指定关卡目录。

- **终端回合展示**：每个有效回合清屏后显示最新状态，再显示本回合消除与红色属性提示；非法输入不清屏、不消耗停滞回合。输出重定向时保留日志，不输出清屏控制序列。

- **模式与属性**：关卡选择前询问是否添加属性；启用后显示完整规则。三种属性各有 10% 概率（总概率 30%），由 CLI 配置传入，核心默认关闭。轨道用 list<Ball>、等待区用 queue<Ball> 保存颜色及属性，弹药仍用 vector<char>。



### 特殊效果的已确定边界



1. 属性球实际被消除时只触发一次，普通入轨、丢弃或回退不会触发。

2. Boom 以该次消除前的位置计算左右各 3 格，端点截断，能引爆范围内其他属性，实际删除的球每颗只计分一次。提示为“Boom: 炸弹清除 第x格到第y格”。

3. Back 在消除阶段完成后，将最前端最多 3 个球按原顺序放回等待区最前端，保留属性；随后本回合照常增长。因此没有停滞时可能立即重新进入一个球。提示实际回退数量。

4. Stop 从下一有效回合开始暂停两回合；多个 Stop 叠加。原有停滞先处理，再增加新触发的暂停时间。提示“Stop: 本回合停滞中”，剩余回合使用红色。

5. 删除阶段只检查产生的断口，不对所有轨道同色段进行全局消除；等待球进入也不触发消除。
