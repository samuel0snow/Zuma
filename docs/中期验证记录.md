## 自动化验证

运行 `cmake --build build`、`ctest --test-dir build --output-on-failure` 及 `node --check web/app.js`。

| 检查 | 验证范围 |
| --- | --- |
| `zuma_rules` | 原始规则、普通/多级连锁、属性、边界及非法核心配置 |
| `zuma_api_rules` | 两关、两种模式的固定种子核心/API 全状态和事件一致性；球 ID 唯一；后退及再次入轨保留 ID；创建/发射/重启幂等；旧版本及旧会话拒绝；事件阶段和得分；非法类型/位置不改状态；胜利和加载失败 |
| `zuma_http_contract` | 启动真实服务，页面资源、真实 POST、错误 JSON、深层 JSON、请求大小限制、同源与 Host 校验、路径白名单、结束后拒绝操作、重复与四路并发请求只推进一次、胜利/失败/重启 |
| JavaScript 语法 | `web/app.js` 由 Node 检查，GUI 运行本身不依赖 Node |

HTTP 检查需要 Python；CMake 找到 Python 时注册该测试，未安装时仍能编译与游玩。测试启动临时服务并在 finally 中关闭，只使用临时演示关卡，不修改附件。

## 浏览器实际操作

- 原始关卡 1，经典模式，位置 4 发射：得分 70、回合 1、轨道剩 G、等待区 13 颗。
- 原始关卡 1 连续丢弃直至超过容量：失败面板显示，丢弃和发射禁用，重新开始回到模式页。
- 原始关卡 2，特殊模式：说明可见，发射与丢弃推进状态；刷新恢复当前关卡、模式和回合。
- 临时演示 `ACTIVE=RR, FEED=空, AMMO=R, MAX_LENGTH=2`：位置 2 发射后胜利、得分 30、回合 1；操作禁用。
- 临时空轨道、有等待球：显示唯一插入位置 1，发射正常。
- 模拟 API 请求中断：游戏操作禁用；恢复后重新连接，未确认的操作没有自动重发。
- 连续触发同一按钮两次：只发送一个 action 请求，只推进一回合。
- 双页面操作：旧版本操作被拒绝并同步；另一页面重启后，旧会话页面也能同步到模式页。
- 键盘 Enter 可以丢弃，玩法说明支持 Escape 关闭。
- 390×844 小屏：文档宽度等于视口宽度，轨道独立横向滚动，状态与发射台没有页面横向溢出。
- 正常操作未见浏览器控制台错误；断线/冲突测试会产生预期的失败网络请求。

## D：动画与素材验收

网页按核心事件播放完整回合，最后以服务快照校正；不在浏览器计算消除规则。实际服务联调使用原始两关及固定种子，Back=1、Boom=2、Stop=9（仅 --test-mode 允许指定）。

- `tests/d_browser_checks.js`：普通/连锁/等待入轨/弹药动画、播放期间操作禁用、跳过后完整同步、减少动态效果、三种属性、第二关、小屏及重启均通过。
- `tests/export_animation_fixtures.cpp` 导出真实核心快照，`tests/animation_fixture_checks.js` 验证 12 个渲染用例：back、boom、chain、empty、loss、stop、stop-skip、win、skip、reduced、unsupported、exception。每例比较最终完整状态及轨道/等待区每颗球的 ID、颜色、属性，确认没有残留临时动画节点。
- 故意阻断球体图片后仍可见 CSS 颜色和字母，并能操作；故意阻断 API 后暂停操作，恢复后同步，未确认操作不重发。

## 浏览器测试复现

常规构建和 CTest 导出 `build/animation-fixtures.json`。浏览器测试是可选开发依赖，运行游戏本身不需要 npm：

```powershell
npm install --prefix build/browser-test-deps --no-save --package-lock=false playwright@1.58.2
node build/browser-test-deps/node_modules/playwright/cli.js install chromium
```

动画渲染测试先用 `python -m http.server 8083 --bind 127.0.0.1 --directory web` 启动静态测试服务，再运行 `node tools/run-browser-checks.mjs renderer http://127.0.0.1:8083`。数据来自 C++ 导出的快照，测试临时拦截 API，不操作玩家正在运行的游戏。

实际服务测试需独立实例：`build/zuma_gui.exe --port 8082 --test-mode`，再运行 `node tools/run-browser-checks.mjs service http://127.0.0.1:8082`。此测试会重置该实例的游戏，不应指向玩家当前使用的服务。结果保存到 `build/browser-*-result.json`。

上述 Node 测试入口也已实际执行通过：renderer 返回 12 个用例，service 返回完整服务检查项及属性种子，不只依赖交互工具中的手工运行。可用 ZUMA_BROWSER_CHANNEL 或 ZUMA_BROWSER_EXECUTABLE 指定开发者已安装的测试浏览器；默认使用对应版本 Playwright Chromium。

## 终局与静态回合复盘（2026-10-14）

- 游戏中可主动结束本局；主动结束不增加回合，也不伪造一条回合记录。胜利、失败与主动结束统一开放“查看复盘”。
- 每个有效回合完成时，服务端直接保存实际结束快照、操作、得分变化、结构化核心事件阶段和事件文案。复盘按回合顺序绘制为一条静态长流程图，展示 TRACK、FEED、当前/下一发射球与事件；打开复盘不会重新运行规则或模拟操作。
- 浏览器服务回归覆盖主动结束、查看实际回合快照及事件、重开返回玩法选择并清空记录。HTTP 合约检查同时覆盖胜利、失败的回合保存、结束后锁定及重启清理。
- 本次全量构建通过；C++ 规则、API 规则、动画跟踪和 HTTP 合约四项 CTest 均通过。浏览器静态渲染覆盖胜利、失败等 13 种用例，服务端实际交互检查覆盖主动结束与复盘流程。
