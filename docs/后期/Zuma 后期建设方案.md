# Zuma 后期建设方案

本文记录已确认的后期地图与发射玩法，以及 2026-10-14 开始的构建进度。目标是在现有 C++ 规则核心和本地网页基础上，加入统一瞄准发射、三类开放轨道地图和清晰的游戏舞台，并保留经典模式、特殊球模式和逐回合复盘。

## 1. 模式与地图

先选择玩法，再选择地图，最后选择关卡：

| 玩法 | 直线地图 | 螺旋类环形地图 | S 形地图 |
| --- | --- | --- | --- |
| 经典模式 | 可选 | 可选 | 可选 |
| 特殊球模式 | 可选 | 可选 | 可选 |

两种玩法都使用同样的三张地图。经典模式不生成特殊属性球；特殊球模式沿用现有规则，Back、Stop、Boom 各有 10% 出现概率。原有两关和较长的第三关供全部地图共用，关卡配置与地图几何独立。第三关初始 16 球、等待 24 球、容量 30，用于长地图及关卡扩展测试。

三张地图都采用瞄准发射。直线地图也从当前“点击编号间隙”改为发射台瞄准。每种地图的轨道、发射台和动画都显示在同一张游戏舞台卡片中。

## 2. 游戏舞台卡片

游戏主画面需要一张尺寸明确的舞台卡片，完整容纳地图轨道、TRACK 彩球、发射台、瞄准辅助线、命中预览、飞行中的球和消除/推移动画。轨道与特效不得绘制到卡片裁切范围之外；尤其是没有显示在 TRACK 可视范围内的球，不应出现消除特效。

舞台卡片使用统一的内部坐标系绘制三种地图。卡片可随浏览器窗口缩放，但场景元素按比例缩放并保持在卡片内。关卡信息、得分和操作控件可以放在卡片周围；用户所说的动画画面均以这张卡片为边界。

直线地图的发射台固定在卡片底部中央。螺旋类环形和 S 形地图可参考所附示例将轨道围绕场景中心构图，发射台放在轨道内侧或中心区域；具体位置仍需结合实际可用空间确定。参考图只用于理解轨道构图，不要求复刻图中的素材或界面。

## 3. 三张地图的轨道约定

### 直线地图

TRACK 沿直线排列，球在回合之间保持静止。发射台位于舞台卡片底部中央，玩家从发射台朝鼠标方向瞄准。发射后，等待区仍按当前回合规则每回合加入一颗球。发射球插入后，插入位置之后的球向轨道顺序方向移动一个球位，表现为受力推移；动画完成后球停在新的位置。

### 螺旋类环形地图

轨道采用手绘图的布局并根据后续反馈加长：开放路径从外围入口进入，绕场景中心盘成至少两圈，当前为 2.15 圈，并在内侧结束。图中的“台”表示发射台，发射台放在轨道内侧、靠近中心的位置。轨道不是闭合圆环：它有明确的入口和终点，TRACK 仍是一条有起点、终点的开放序列。路径两端即使在画面上靠近，也不视为逻辑相邻；球不会跨轨道首尾消除或连锁。

等待球从入口进入开放轨道，容量和失败判定沿用关卡的 MAX_LENGTH。此前提出的“闭环容量为初始 ACTIVE 的两倍”不再适用。轨道具体曲线由实现阶段绘制，并通过实际布局试验确定盘绕圈数、圈间距、入口与终点位置。

界面中的“终点”按本关 MAX_LENGTH 自动定位，放在最后一个合法球位与第一个超限球位之间，而不是完整曲线的末端。终点后的多余曲线作为淡化背景保留，不再标出另一个终点或“容量边界”；回合结束时越过该终点对应轨道超限失败。复盘使用同一终点位置。

### S 形地图

TRACK 采用本轮第二张手绘图所示的横向 S 形开放路径，具有明确入口和终点；发射台“台”位于轨道下方。等待球从入口进入；轨道球在回合之间保持静止。插入和等待球入轨时，沿路径顺序推移后续球，完成动画后停下。S 形路径上画面距离很近但序号不相邻的两段，仍按空间位置接受射线碰撞；消除和连锁则只按 TRACK 的序列邻接关系判断。

## 4. 统一瞄准、命中与插入规则

发射台中心到鼠标位置构成瞄准辅助线。实际发射沿发射台指向鼠标的射线前进；如果射线经过多颗 TRACK 球，选择沿射线最先接触的球作为目标。曲线地图中，路径在屏幕上靠近的不同轨段也参与实际空间碰撞，不能越过先碰到的球选中后面的球。

瞄准目标不只限于射线穿过球体的情况。射线与两个相邻 TRACK 球的球心连线段相交，也算命中两球间隙，直接在两球之间插入。球体与相邻球间隙共同作为拦截目标，沿射线选择最先遇到者：前排间隙会挡住射线，不会透过空隙选择后排球。本规则已在开始构建时确认，不适用于 TRACK 序列中不相邻、但画面位置接近的两颗球。

插入侧由目标球球心处分界线决定：

1. 按 TRACK 的排列方向，求目标球位置处的轨道切线。
2. 经过目标球球心并垂直于该切线的直线作为分界线，将目标球分成 TRACK 正方向侧和反方向侧。
3. 观察瞄准射线穿过目标球时落在分界线哪侧，据此选择目标球前或后的插入间隙。
4. 如果射线恰好落在球心分界线上，固定选择 TRACK 正方向侧。

直线从左向右排列时，规则表现为穿过目标球左半侧就插入左边，穿过右半侧就插入右边。弯曲地图按照目标球处的局部轨道方向判定，不使用屏幕绝对左右。判断依据是辅助线穿过球时相对球心分界线的位置，不是鼠标指针落在球图上的位置。

发射前应显示瞄准线、首个命中球高亮、分界线提示和预计插入间隙，让玩家能预判发射结果。

### 没有命中 TRACK 球：吐球

如果瞄准射线没有穿过任何 TRACK 球，也没有命中上述相邻球之间的间隙，本次发射作为“吐球”处理。吐球就是弃用当前球：球沿瞄准辅助线继续飞行，直到到达舞台卡片边缘后消失，然后完全复用主动丢弃球的回合结算，包括当前弹药消耗、回合推进、等待区 FEED 推进和 Stop 状态处理。吐球不插入 TRACK，也不触发命中、消除或推移效果。

## 5. 插入、吐球与推移动画

本项目不需要先引入完整物理引擎。地图路径可由网页 SVG 定义，彩球按路径距离均匀排布；每张地图提供轨道曲线、入口、起点到终点的方向和可视范围。几何尺寸以现有代码中的球体直径为基准：球沿轨道排列时，中心间距为球体直径的 1.5 倍，即球面之间留半个球径；路径安全边距按一个球体直径计算，保证射线不能从前排球之间的空隙穿到后排球。舞台卡片、轨道和发射台的可用空间需据此反推，不缩放球体来迁就未经验证的路径。

瞄准通过射线与球体的相交计算找出首个目标；另对相邻球球心连线上的狭窄间隙进行判定。局部切线和垂线用于球体命中时判定插入侧。路径安全边距是布局与判定约束，不改变 TRACK 的逻辑顺序。

状态更新仍按离散回合执行。命中时，发射球飞到预览间隙并插入，插入侧后方的球沿 TRACK 方向移动一个球位；等待球从入口入轨时也使用推移动画。未命中时，发射球沿辅助线飞到舞台卡片边缘并消失，播放完成后结算该回合。动画状态使用稳定球 ID 和权威状态确定位置；减少动态效果、跳过动画或播放异常时，页面直接显示本回合最终状态。

地图路径和舞台卡片必须共用裁切边界。动画粒子、消除光效和飞出舞台的吐球也受卡片边界约束；吐球到达边缘时结束显示，避免画面穿模。

这类路径碰撞和插入推移属于轻量几何与界面动画。以后若希望彩球持续运动、反弹、相互碰撞或受力后惯性滚动，再评估游戏引擎或物理库是否值得引入。

## 6. 游戏核心与页面职责

规则仍由 C++ 核心和本地服务负责，浏览器负责绘制轨道、瞄准预览和动画。后期 API 应提交地图 ID 与瞄准射线（发射台起点和方向，使用地图统一坐标系），由服务端结合当前 TRACK 和地图路径求首个命中球、插入侧或吐球结果。响应事件应包含地图标识、目标球 ID、射线命中顺序、插入间隙、受推移球 ID 或吐球事件，以及回合阶段快照。

关卡配置与地图几何分开：关卡提供球序列、弹药和 MAX_LENGTH；地图提供路径、入口、方向及舞台绘制信息。三种地图都使用开放 TRACK 序列，避免网页自行改写球序。

终局复盘保留每回合实际结束状态和事件。新增地图后，每个回合记录应能说明地图、瞄准目标、插入侧、受推移球或吐球结果，以便复查。

## 7. 建设顺序

1. **舞台卡片与地图数据分层**：建立统一场景坐标系和裁切范围；加入“玩法 → 地图 → 关卡”选择；两种玩法和现有两关均可访问三张地图。
2. **直线地图瞄准**：加入射线、首球命中、相邻球间隙命中、插入侧判断、正方向平局规则、插入预览和未命中吐球。
3. **直线推移与复盘事件**：实现插入后球列推移、吐球飞向卡片边缘，以及对应的跳过动画和复盘记录。
4. **S 形开放地图**：验证弯道、近邻轨段、端点、擦边及同一射线经过多个球的情况。
5. **螺旋类环形开放地图**：绘制盘绕但不闭合的轨迹，明确入口和终点，验证端点不相邻且容量遵循 MAX_LENGTH。
6. **统一验收与课程报告**：对经典和特殊球玩法分别验证三地图、两关、胜败和复盘，更新课程报告与运行说明。

## 8. 验收重点

- 经典和特殊球模式均可选择直线、螺旋类环形和 S 形地图；现有两关配置可复用。
- 三种地图的游戏动画都完整显示在舞台卡片内；轨道球、发射台、瞄准线、飞球和效果不越过卡片裁切边界。
- 直线地图发射台位于舞台卡片底部中央；瞄准首球、插入侧与页面预览一致。
- 射线经过多个球时选择最先接触者；恰好落在球心分界线时选择 TRACK 正方向侧。
- 射线未穿过球体且没有穿过相邻球球心连线间隙时触发吐球动画；吐球到达卡片边缘后消失，并完全复用弃球的弹药、回合、FEED 和 Stop 结算。
- 射线与两颗相邻 TRACK 球的球心连线段相交时，能插入这两个球的间隙，前排间隙拦截后排目标；对应间隙预览与实际结算一致。
- 螺旋类环形和 S 形都是开放轨道；画面上靠近的端点或轨段不会改变 TRACK 的序列邻接关系。
- 发射、等待球入轨和推移动画完成后，TRACK 顺序、球 ID、得分、回合、FEED、AMMO 与 C++ 权威状态一致。
- 复盘保存每回合真实快照和事件，能识别地图及插入/吐球结果；重开新局后清空上一局记录。
- 低动态效果、跳过动画、浏览器刷新和请求冲突均能回到服务端最终状态。

## 9. 后续布局微调

- 发射台位置已经按手绘图确定：螺旋地图中心内侧，S 形地图下方，直线地图底部居中。曲线形状与构图可以根据实际体验继续微调。
- 轨道间距和路径安全边距按现有球体直径推导：中心间距为 1.5 倍球径，安全边距为 1 倍球径。其余间距在绘制与桌面验证过程中调整；微调不改变球序、容量或瞄准拦截规则。

## 10. 构建进度（2026-10-14）

用户已授权按本方案开始构建。GUI 改为瞄准操作，CLI 保留编号发射，继续共用既有消除与特殊球规则。三张地图都采用开放轨道。

- 已加入“玩法 → 地图 → 关卡”的选择流程，经典与特殊球模式均可使用三张地图和两关。
- C++ 地图模块提供场景尺寸、路径采样、固定发射台、球位与方向；服务端决定最先命中的球/间隙、插入侧和吐球结果。
- 页面预览使用服务端导出的同一份几何数据；只提交射线方向，发射起点由服务端固定，不允许网页改写插入位置。
- 直线与 S 形地图的世界坐标球径为 68，球心沿路径间距为 102，安全边距为 68。螺旋地图根据反馈缩小为球径 44、间距 66、安全边距 44，并把轨道加长至 2.15 圈；原有两关容量保持 12/15，第三关为 30，多余路径为空。场景整体等比例缩放，发射球及底座按球径同步适配。卡片尺寸与地图画布比例一致，吐球的前缘到达卡片边缘后消失。
- 插入与等待球入轨推动后续球沿曲线路径移动；消除、Boom 和其他临时动画放在舞台裁切层内。
- 吐球实际调用核心弃球逻辑，保留独立的吐球动画、事件和复盘标识；FEED、Stop、AMMO 与回合结算保持一致。
- 结束后的复盘展示每回合真实快照、地图缩略图、射线和事件；重开清空旧局。
- 三种桌面尺寸的布局验收及规则/接口验证记录见 [后期建设验证记录](../审核记录/后期建设验证记录.md)。
- 新增 `levels/level3.txt`，CLI 和 GUI 自动扫描关卡目录中规范命名的 `levelN.txt`，支持不连续编号；构建自动复制匹配的关卡文件，增加第四关不必修改菜单或 API 的编号上限。
- 修正物理路径末端与容量失败位置不一致的误导：终点改为容量边界，后续路径淡化。页面采用较大舞台与右侧信息区，等待球、操作、回合事件和结束结果集中在侧栏；移除原先包住全部内容的大块暗色面板，并提高场景亮度。
