# Zuma 游戏事项PRE

## 编程总纲

1. 使用 C++ 实现游戏核心与 CLI；中期考虑使用 H5（HTML、CSS、JavaScript）实现 GUI。

2. 数据结构选择

| 数据 | 数据结构 | 使用位置与选择原因 |
| --- | --- | --- |
| AMMO | 数组 `vector<char>` | 保存循环弹药，通过下标与取模访问当前球和下一个球。 |
| TRACK | 双向链表 `list<char>` | 保存轨道内的球，支持任意位置插入、左右查找和连续区间删除；按编号定位需要遍历。 |
| FEED | 队列 `queue<char>` | 保存等待球，每个有效回合取出队首，符合先进先出的顺序。 |

定义 TRACK 为玩家看到的轨道，初始化内容为 ACTIVE。FEED 独立保存在等待区，进入轨道后才属于 TRACK。

**说明**：课堂检查需要说明各数据结构的使用位置、选择原因和作用。

3. 模块划分

- 关卡读取：解析并验证文件，生成关卡配置。
- 游戏核心：维护轨道、等待区、弹药下标、得分、回合数和胜负状态。
- 回合处理：验证操作，执行消除、自动增长、弹药更新和胜负判断。
- 交互显示：CLI 读取命令并打印状态；GUI 提交操作并展示结果。

## 初期：CLI 形式

### 1. 关卡选择与读取：

启动后显示关卡列表，通过输入 `1`、`2` 等编号选择，读取对应的 `level1.txt`、`level2.txt`。

```text
ACTIVE=RRBBRR
FEED=GBYPRGBGYRBPYG
AMMO=BBGYRRGBYPRG
MAX_LENGTH=12
```

- 按行读取，以 `=` 分隔字段名与值，去除首尾空白及换行符。
- 检查四个字段是否齐全、是否重复，MAX_LENGTH 是否为正整数。
- 颜色暂定为 `R`、`G`、`B`、`Y`、`P`，分别表示红、绿、蓝、黄、紫，其他字符视为错误。
- ACTIVE 与 FEED 可以为空；AMMO 不可为空。只有一种弹药时，当前球和下一个球均为该颜色。
- 初始 ACTIVE 长度不得超过 MAX_LENGTH。文件缺失或格式错误时提示原因，并返回关卡选择。
- ACTIVE 写入 TRACK，FEED 依次入队，得分与回合数初始化为 `0`。
- AMMO 的第一个字符为当前球，第二个字符为下一个球，按循环规则读取。
- 初始化后检查胜负状态：初始轨道和等待区均为空时，直接胜利。

### 2. 彩球发射、插入与丢弃：

通过 `| |` 表示一格，已有球依次显示，剩余容量显示为空格。

**e.g.** CLI 初始状态如下：

```text
关卡: 1    得分: 0    回合数: 0
轨道长度: 6 / 12
|R|R|B|B|R|R| | | | | | |
插入位置: 1 2 3 4 5 6 7

当前球 |B|    下一球 |B|
等待区: GBYPRGBGYRBPYG（剩余 14 个）

输入位置发射，输入 q 丢弃，输入 exit 退出:
```

1. 可使用终端 ANSI 颜色展示彩球，同时保留字母，便于在不支持颜色的终端阅读。

2. 若已有 `n` 个球，合法插入位置为 `1` 至 `n + 1`。位置 `i` 表示原第 `i` 个球之前，`n + 1` 表示末尾；空轨道只有位置 `1`。插入位置对应球之间的间隙，与容量格不同。

3. 轨道达到上限时仍允许插入，完成消除和自动增长后才判断失败。

4. 整行读取并严格解析命令。空输入、非整数、带多余字符的数字、越界位置等均提示错误并重新输入，不改变任何游戏状态。

5. `q` 丢弃当前球，属于有效回合；`exit` 主动退出，不计入回合，也不算游戏失败。

6. 每个有效回合的顺序如下：

   1. 发射并插入当前球，或丢弃当前球。
   2. 发射时完成普通消除及全部连锁消除；丢弃不触发消除。
   3. 若 FEED 非空，将队首球加入 TRACK 最前端并出队。
   4. 更新当前球和下一个球，回合数加 `1`。
   5. 判断胜负并显示状态，未结束则等待下一次操作。

**说明**：等待球从轨道最前端进入是本项目的设计选择，应在报告中说明。等待球加入本身不触发消除。

### 3. 普通消除与连锁消除：

以插入球为起点，向左右查找连续同色球，统计包含该球的同色区间。

- 长度小于 `3`：不消除，结束消除阶段。
- 长度至少为 `3`：删除整个区间，不只删除三个球。
- 删除后，若断口两侧都有球且颜色相同，继续向左右扩展并统计同色区间。
- 新区间长度至少为 `3` 时继续删除并检查新断口；否则停止。
- 断口在轨道端点，或两侧颜色不同，也停止连锁消除。
- 删除链表区间时保留断口两侧的有效迭代器，不访问已删除节点。

**普通消除**：向 `RR` 插入 `R`，形成 `RRR`，全部消除。

**连锁消除**：向 `RRBBRR` 的两个 `B` 之间插入 `B`，形成 `RRBBBRR`；消除 `BBB` 后剩下 `RRRR`，再消除四个 `R`。随后仍需加入等待球，不能立即判断胜利。

计分暂定为每消除一个球获得 `10` 分，连锁按实际数量累计；丢弃和等待球加入不加分。

### 4. 轨道自动增长

每次成功发射或丢弃，在消除阶段结束后，从 FEED 队首取出一个球，加入 TRACK 最前端。

- 每个有效回合最多加入一个等待球，FEED 为空时不再加入。
- 非法输入不会触发增长，增长也不消耗 AMMO。
- 自动加入不直接触发消除；后续发射可以消除包含插入球的同色区间及其连锁区间。

使用 `ammoIndex` 表示当前弹药位置：

```cpp
currentBall = ammo[ammoIndex];
nextBall = ammo[(ammoIndex + 1) % ammo.size()];
```

每个有效回合结束时执行以下更新，再重新计算当前球与下一个球：

```cpp
ammoIndex = (ammoIndex + 1) % ammo.size();
```

这样下一个球成为当前球，弹药到达末尾后从头生成，不存在弹药耗尽。

### 5. 游戏状态与胜负判断

显示关卡、轨道、轨道长度与上限、当前球、下一个球、等待区、得分及回合数。

完成整个有效回合后统一判断：

- TRACK 和 FEED 同时为空：胜利。
- TRACK 长度超过 MAX_LENGTH：失败。
- 其他情况继续，长度恰好等于上限时仍可操作。

结束时显示结果、最终得分和回合数，提供重新选择关卡或退出选项。重新开始必须重置全部状态。

### 6. 初期验证与演示准备

- 使用两个附件关卡验证读取、选择与初始化。
- 使用 `RR` 与当前球 `R` 验证普通消除，使用 `RRBBRR` 与当前球 `B` 验证连锁消除。
- 连续丢弃，检查等待球每回合只加入一个、弹药正确循环。
- 输入空行、字母、带多余字符的数字及越界位置，检查状态不变。
- 验证长度等于上限时继续、超过上限时失败，以及轨道和等待区均为空时胜利。
- 验证轨道暂时清空但等待区非空时不会提前获胜，自动加入也不会自行消除。
- 可另加演示关卡，保留附件原始关卡；保存典型运行截图用于报告。

## 中期：GUI 实现

### 1. 语言与实现方式：H5

CLI 完成并验证后，再实现 GUI。GUI 属于可选扩展，CLI 保持独立可运行。

- HTML 组织关卡选择、轨道、弹药、等待区和状态栏。
- CSS 绘制彩球、插入位置和按钮。
- JavaScript 处理点击、请求、状态渲染及消除动画。
- C++ 保留全部游戏规则与状态管理。

浏览器不能直接调用本地 C++ 程序。暂定采用 **C++ 本地 HTTP 服务 + H5 页面**：服务仅监听本机地址，提供页面，并通过 HTTP 接收操作、返回 JSON 状态。具体网络库在实现时选择，在运行说明中列出依赖和启动步骤。

将游戏核心与 CLI 输入输出分离，GUI 服务调用同一核心，保证两种界面规则一致。

### 2. GUI 界面

界面细节对应 CLI，通过按钮和点击位置实现发射与丢弃。

- 顶部：关卡选择、开始游戏、重新开始。
- 状态栏：得分、回合数、轨道长度及上限。
- 轨道区：依次显示彩球，在球之间及两端显示 `n + 1` 个可点击插入位置。
- 弹药区：突出显示当前球和下一个球，提供“丢弃”按钮。
- 等待区：显示球的顺序和剩余数量，过长时可横向滚动。
- 提示区：显示操作结果、错误信息和胜负提示。

彩球同时用颜色和字母标识；空轨道仍提供一个插入位置。游戏结束后禁用发射与丢弃，提供重新开始入口。

### 3. GUI 交互与状态同步

1. 选择关卡后请求初始化游戏，展示返回状态。
2. 点击插入位置提交发射命令及位置；点击“丢弃”提交丢弃命令。
3. C++ 验证操作、处理完整回合，返回最终状态与各阶段变化，供动画展示。
4. 前端依次展示插入、普通消除、连锁消除和等待球进入，最后更新弹药、得分、回合数及胜负状态。
5. 请求与动画期间禁用操作，避免重复点击导致回合重叠。
6. 请求失败时提示错误并重新获取服务端状态，不自动重发发射或丢弃命令，避免重复执行回合。

**说明**：动画只展示处理过程，操作合法性、消除及胜负均由 C++ 核心决定。

### 4. 中期验证与交付准备

- 同一关卡执行相同操作序列，对比 CLI 与 GUI 的全部状态。
- 检查空轨道、满轨道、连锁消除、等待区为空和游戏结束的显示。
- 检查快速重复点击及服务连接失败的处理。

## CLI 健壮性复查与补充（2026-10-13）

### 已完成的改进

- **缺失文件诊断**：使用 `is_open()` 明确检查关卡及目录探测文件是否打开，缺失文件报告“无法打开关卡文件”，不混淆成缺少字段；已增加回归测试。
- **核心配置校验**：除文件解析外，`Game` 构造函数也验证 ACTIVE、FEED、AMMO 的颜色、非空弹药、正容量、初始长度、属性概率范围 0…100、初始属性数量和属性枚举。后续 GUI 直接调用核心时也不能绕过这些检查。
- **极大容量显示保护**：轨道中的球全部展示，空格最多额外展开 20 格；其余空格显示数量，避免合法但极大的 MAX_LENGTH 导致巨量输出。此措施只限制显示，不改变游戏容量和合法插入位置。
- **关卡选择阶段重启**：输入 restart 可返回属性模式选择；游戏进行中重启清屏、丢弃旧局，重新选择后初始化全部状态。主动重启不是游戏失败，也不是有效回合。
- **构建资源定位**：CMake 在构建完成后将原始关卡复制到可执行文件旁的 levels/，兼容普通及多配置输出目录。支持 --levels 指定关卡目录。
- **终端回合展示**：每个有效回合清屏后显示最新状态，再显示本回合消除与红色属性提示；非法输入不清屏、不消耗停滞回合。输出重定向时保留日志，不输出清屏控制序列。
- **模式与属性**：关卡选择前询问是否添加属性；启用后显示完整规则。三种属性各有 10% 概率（总概率 30%），由 CLI 配置传入，核心默认关闭。轨道用 list<Ball>、等待区用 queue<Ball> 保存颜色及属性，弹药仍用 vector<char>。

### 特殊效果的已确定边界

1. 属性球实际被消除时只触发一次，普通入轨、丢弃或回退不会触发。
2. Boom 以该次消除前的位置计算左右各 3 格，端点截断，能引爆范围内其他属性，实际删除的球每颗只计分一次。提示为“Boom: 炸弹清除 第x格到第y格”。
3. Back 在消除阶段完成后，将最前端最多 3 个球按原顺序放回等待区最前端，保留属性；随后本回合照常增长。因此没有停滞时可能立即重新进入一个球。提示实际回退数量。
4. Stop 从下一有效回合开始暂停两回合；多个 Stop 叠加。原有停滞先处理，再增加新触发的暂停时间。提示“Stop: 本回合停滞中”，剩余回合使用红色。
5. 删除阶段只检查产生的断口，不对所有轨道同色段进行全局消除；等待球进入也不触发消除。

### 验证记录

已在本机 MinGW/C++17 构建并通过 CTest。测试覆盖普通消除、多级连锁、满轨道发射、胜负边界、非法操作状态不变、弹药循环、读取错误、Stop 的后续两回合、Back 顺序与属性保留、Boom 半径与引爆、固定随机种子，以及本次补充的直接核心非法配置校验。

CLI 冒烟验证补充：关卡选择阶段 restart、模式切换后的状态归零、文件缺失后返回选择、超大容量省略空格。终端颜色和清屏有纯文本/重定向回退；Windows 以外平台与 MSVC 尚需在对应环境实测，不能视为已验证。

### 螺旋地图两圈优化

根据体验反馈，将螺旋地图由 1.13 圈延长至 2.15 圈，球径由 68 缩为 44，球心路径间距为 66，安全边距为 44；相邻圈的球边缘之间至少留出一个球径。关卡容量继续为 12/15，多余物理路径留空。前端不再硬编码轨道球大小，绘制、命中、发射台、飞球及复盘共同适配地图尺寸。已补充两圈与实际圈间距检查，并更新螺旋地图截图。

### 第三关与关卡自动发现

新增 `levels/level3.txt`：ACTIVE 为 16 球，FEED 为 24 球，AMMO 为 16 颗循环弹药，MAX_LENGTH 为 30。初始球采用同色双球段，不预置三连；方便选择插入点测试消除，也可连续弃球测试容量边界。

CLI 与 GUI 自动扫描规范命名的 `levelN.txt`（正整数 N，按编号排序），不再把可选关卡固定为 1/2。CMake 自动收集并复制关卡文件。GUI 每次读取关卡列表时重新扫描，新增文件后不必修改代码或重启服务；默认运行目录为可执行文件旁的 `levels/`，项目根目录新增文件需要先构建复制，或通过 `--levels` 直接指定目录。

验证覆盖第三关在三地图/两玩法下的创建与推进、CLI 选择第三关、不连续编号 7/9、运行中发现新文件、无效文件名过滤和不存在的关卡拒绝。长关卡的选择预览自动换行，避免撑出卡片。

### 终点与布局反馈修正

视觉终点不再使用完整几何路径末端，而是根据 MAX_LENGTH 标在最后合法球位与第一个超限球位之间。超过终点与核心容量判负一致；多余轨道淡化，删除另一处“容量边界”，主舞台和复盘共用终点绘制。

页面移除包围小地图的大块暗色面板，增大舞台，把等待区、下一球、操作、回合事件与结果放入侧栏；结束时保持舞台尺寸和球的颜色亮度。桌面验收增加终点与容量一致、失败截图及布局完整显示检查。
